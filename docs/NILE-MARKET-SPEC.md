## أ. الهوية والهدف
منصة SaaS سودانية لإنشاء وتشغيل متاجر إلكترونية متعددة التجار. كل تاجر
يحصل على **متجر ويب مستقل** ولوحة إدارة خاصة. واتساب جزء أساسي من تجربة
البيع. عربي RTL من البداية. سريع وآمن وقابل للتوسع.
**الإطلاق الأول يشمل كل ميزات هذه الوثيقة — لا تأجيل.**

## ب. المبدأ الحاكم
الميزة لا تكتمل بظهور واجهتها. الاكتمال =
`تصميم + واجهة + منطق خلفي + قاعدة بيانات + صلاحيات + أمان + حالات خطأ + اختبارات`.
**كل متجر معزول على مستوى قاعدة البيانات، لا الواجهة.**

## ج. التقنية (محسومة)
Next.js + TypeScript · Supabase (PostgreSQL + Auth + Storage) · Vercel ·
Multi-Tenant · البدء على Supabase Free وVercel Free مع تصميم قابل
للترقية **بلا إعادة بناء** · لا خدمات مدفوعة إضافية بلا حاجة واضحة أو
قرار صريح · **ممنوع** تخزين الأسرار في الواجهة.

`Nile Blue #0B5ED7` · `Deep Navy #0B1F3A` · `White #FFFFFF` ·
`Light Gray #F5F7FA` · `Gold #D9A441` (Accent فقط).
Design System موحد · Mobile First · RTL حقيقي · تصميم متجر موحد بتخصيص
محدود · **لا نسخ لتصميم أو أصول أي منصة أخرى**.

## هـ. القواعد المالية (محسومة — لا اجتهاد فيها)
1. عمولة الشريك = **50% من صافي المبلغ المحصَّل فعليًا بعد الخصم**.
   مثال معتمد: 20,000 − 5,000 = 15,000 ⇒ **7,500** للشريك و**7,500** للمنصة.
2. **لا دفع ⇒ لا عمولة.** العمولة لا تُحسب من قيمة ترسلها الواجهة.
3. كل اشتراك/تجديد/ترقية مدفوعة تولّد عمولة. علاقة الإحالة **دائمة**.
4. تخفيض الباقة **لا** يولّد عمولة سالبة.
5. الاسترداد الكامل ⇒ Commission Reversal (**لا حذف** للأصل)؛ الجزئي
   يعكس النسبة المقابلة.
6. تغيير نسبة شريك يسري على **المستقبل فقط**.
7. الشريك لا يعدّل نسبته ولا علاقة الإحالة.
8. Commission Ledger وسجلات مالية **غير قابلة للتلاعب من الواجهة**.
9. منع احتساب نفس العملية مرتين.
10. v1: النظام يحسب المستحقات و**Admin يسجّل الدفع يدويًا**.
11. المبالغ المالية تُخزَّن بدقة — **لا Floating Point**.
12. العملة الافتراضية **SDG** · التوقيت **Africa/Khartoum**.

## و. الدفع (محسوم)
v1: **التحويل البنكي · بنكك حسب التكامل الرسمي/المتاح فقط · الدفع عند
الاستلام إن فعّله التاجر.** ❌ لا بوابات إلكترونية أخرى. ❌ **ممنوع
اختراع API لبنكك.** ✅ المعمارية تقبل بوابات لاحقة بلا إعادة بناء
Order/Financial Core. أي تكامل مستقبلي: Webhook Verification +
Idempotency + Audit Logging.
`Payment` منفصل عن `Order`، وحالاته: `Pending · Paid · Failed · Refunded`.
**الإجمالي يُحسب خادميًا؛ لا ثقة بقيمة من المتصفح.**

## ز. الاشتراكات (محسوم)
3 باقات عند الإطلاق (مجانية · أساسية · احترافية) — أسماؤها وأسعارها
وحدودها قابلة للتعديل من Admin. كل باقة: سعر ومدة وحدود ومميزات.
Entitlements تُتحقق في **الواجهة والخادم**، لا الواجهة وحدها.
تجاوز الحد ⇒ رسالة واضحة + خيار ترقية، **لا فشل غامض**.
دورة الحياة: `Trial · Active · Expiring · Grace · Expired · Suspended`.
**انتهاء الاشتراك لا يحذف بيانات المتجر.** Downgrade لا يحذف تلقائيًا —
يمنع الإضافات الجديدة فوق الحد فقط.

## ح. الطلبات (محسوم)
الحالات: **جديد · مؤكد · قيد التجهيز · تم الشحن · مكتمل · ملغي**.
رقم طلب فريد · تفاصيل كاملة · منع الطلبات المكررة عند الضغط المتكرر ·
صلاحيات تغيير الحالة حسب الدور · صفحة نجاح واضحة · متابعة الطلب.
الإجمالي = قيمة المنتجات + التوصيل − الخصومات.
التاجر يحدد المدن والمناطق وأسعار التوصيل وتفعيل COD.

## ط. الصلاحيات (محسوم)
**داخل المتجر:** Owner · Manager · Orders · Products · Customer Service
— قابلة للتوسع · كل موظف حساب منفصل · **التحقق في السيرفر وقاعدة
البيانات** · سجل نشاط لكل عملية حساسة.
**في المنصة:** موظفو Admin بصلاحيات **لكل قسم** ومستويات
`View · Create · Edit · Delete · Approve · Manage`.
**Page Permission وحدها لا تكفي** — تُطبَّق Data Access Matrix: موظف
الدعم **لا يرى** البيانات المالية الحساسة، ولا يصل أحد لبيانات خارج
نطاقه. صلاحيات Admin **قابلة للتدقيق وليست حسابًا خارقًا غير مسجَّل**.

## ي. الدومينات (محسوم)
نطاق فرعي مجاني لكل متجر (`store.nilemarket.online`) — **جزء أساسي من
المتجر**. Custom Domain حسب الباقة/الصلاحيات.
التحقق من الملكية قبل التفعيل · حالات الدومين الكاملة · Primary Domain ·
www وRedirect · **منع ربط نفس الدومين بأكثر من متجر** · **منع Domain
Takeover** · إعادة تحقق عند إعادة الربط.
`Hostname → Store ID → Store Data` قبل عرض أي محتوى.
❌ **لا Supabase Custom Domain لكل متجر** — طبقة Routing/Hosting هي
المسؤولة. ❌ **لا مشروع استضافة لكل متجر.**
عند تفعيل الدومين المخصص: الروابط وSEO وSitemap وOpen Graph تستخدم
الدومين الأساسي. Downgrade **لا يحذف** الدومين.

## ك. المراسلة والدعم (محسوم)
❌ **لا Chat داخلي عام.** ✅ نظام الدعم هو **قناة المراسلة الوحيدة**:
Support Tickets + رسائل + **Internal Notes لا تظهر لصاحب التذكرة**.
الحالات: `New · Open · In Progress · Waiting for Customer · Waiting ·
Resolved · Closed` — ولا تتغير بلا صلاحية أو بطريقة غير منطقية.
عزل التذاكر بين المتاجر إلزامي · المرفقات محمية بسياسات Storage ·
سجل الدعم لا يُحذف بإغلاق حساب خصوصًا مع عملية مالية أو نزاع.

## م. قواعد التنفيذ الملزمة
1. لا تنفيذ كبير قبل اعتماد Architecture + Schema + Security + UI + خطة.
2. **لا اختراع Business Rules** تمسّ المال أو الاشتراكات أو الصلاحيات.
3. لا صفحات وهمية ولا أزرار معطّلة ولا بيانات Mock في النسخة النهائية.
4. كل ميزة مربوطة فعليًا بالـBackend/Database.
5. كل عملية حساسة تُنفَّذ وتُتحقق على الخادم وقاعدة البيانات.
6. Security by Design + Least Privilege.
7. اختبار RLS وعزل المتاجر **فعليًا**.
8. Design System موحد، لا تصميم مختلف لكل صفحة.
9. أداء جيد على الهاتف والإنترنت الضعيف.
10. **لا حذف بيانات تاجر** بسبب انتهاء الباقة.
11. **لا حذف سجلات مالية أو عمولات** بحذف مستخدم أو متجر.
12. معاملات وIdempotency للعمليات المالية والحساسة.
13. بعد التنفيذ: **تشغيل الاختبارات وإصلاح الأخطاء**، لا مجرد الإبلاغ عنها.

## ن. تعريف النجاح
Nile Market جاهز فقط حين تعمل المنصة فعليًا من التسجيل حتى إنشاء المتجر
وإضافة المنتج واستقبال الطلب وإدارته والدفع/التسجيل المالي والاشتراك
والعمولة والصلاحيات والإشعارات، **مع عزل المتاجر وأمان مناسب واختبارات
ناجحة وتجربة Responsive كاملة**.
المعيار ليس جمال الواجهة — المعيار أن النظام **كامل ومترابط وقابل
للاستخدام والصيانة والتوسع**.
