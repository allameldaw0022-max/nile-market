# مساعد الدعم — كيف يعمل، وكيف تتحكّم فيه

نظامٌ يقرأ تذكرة التاجر، يبحث في قاعدة معرفةٍ مكتوبة، ثم **يردّ
تلقائيًّا** أو **يحوّلها إليك** في تلغرام.

يعمل على الإنتاج منذ ٢٠٢٦/١٠/١٥.

---

## ١. المسار كاملًا

```
تاجر يكتب رسالة في تذكرة
        │
        ▼  محفّز القاعدة (0074) — غير متزامن، لا يُبطئ التاجر
  support-agent  (دالّة طرفية)
        │
        ├─ بوّابات: تاجر؟ · غير مغلقة؟ · غير عاجلة؟ · لم يُجب بشريّ؟
        ├─ مطالبة ذرّية بالتذكرة (صفّ واحد لكل تذكرة أبدًا)
        ├─ تمثيل السؤال متجهيًّا (Gemini) ← بحث في ٣٥ مقطعًا
        ├─ النموذج (DeepSeek) يكتب جوابًا + ثقة + needs_human
        │
        ├──▶ ردّ مباشر للتاجر   (AI_MODE=auto وثقة ≥ العتبة)
        ├──▶ مسوّدة لك في تلغرام بزرَّين   (AI_MODE=draft)
        └──▶ «تذكرة تحتاجك» لك في تلغرام  (تحويل)
```

**الزمن المقيس على أوّل تذكرة حقيقية: ثانيتان** من كتابة التاجر إلى
وصول الردّ.

---

## ٢. ما يردّ عليه، وما يصلك أنت

**يردّ تلقائيًّا** على أسئلة التجّار التي يجد جوابها في
`docs/support-knowledge-base.md`: المنتجات · الخيارات · المخزون ·
الطلبات · الباقات · الدومين · رسائل الخطأ · المشاكل الشائعة.

**يصلك أنت** — ولا يردّ:

| الحالة | أين تُفحص |
|---|---|
| دفعة أو تحويل أو فاتورة بعينها | التعليمات (`prompt.ts`) |
| حذف حساب أو متجر، تغيير مالك | التعليمات |
| شكوى على موظّف · تهديد قانوني | التعليمات |
| خلل تقنيّ يحتاج الفريق | التعليمات + قاعدة المعرفة |
| تذكرة **عاجلة** | بوّابة في `decide.ts` |
| تذكرة **زبون أو شريك** | بوّابة في `decide.ts` |
| لا مقطع فوق عتبة التشابه | بوّابة في `decide.ts` |
| ثقة النموذج دون العتبة | قرار في `decide.ts` |

★ **ولا يدخل على محادثةٍ أجاب فيها بشريّ.** المساعد **مجيبٌ أوّل**:
دورٌ واحد لكل تذكرة، ثم هي للبشر. (قيدُ فرادةٍ في المخطّط، لا شرطٌ
في الكود.)

## ٣. المفاتيح التي تُغيّر السلوك

كلّها في **أسرار الدوالّ الطرفية** في لوحة Supabase. وتسري عند أوّل
إقلاع بارد للدالّة — ★ لا عند حفظها.

| المتغيّر | الافتراضي | أثره |
|---|---|---|
| `AI_MODE` | `draft` | `auto` = يردّ مباشرةً · `draft` = يرسل لك مسوّدة |
| `AI_MIN_CONFIDENCE` | `0.75` | أقلّ ثقةٍ يُرسل بها في وضع `auto` |
| `AI_MIN_SIMILARITY` | `0.65` | أقلّ تشابهٍ يُقبل به مقطعُ معرفة |
| `LLM_PROVIDER` | `deepseek` | `openai` أو أي مزوّد متوافق |
| `LLM_MODEL` | `deepseek-chat` | اسم النموذج |
| `LLM_TEMPERATURE` | `0.2` | ★ ليست صفرًا: صفرٌ يكرّر صيغةً واحدة في كل تذكرة |
| `SITE_URL` | `https://nilemarket.online` | تُبنى منه روابط التذاكر في تلغرام |

**لإيقاف الردّ التلقائي فورًا:** احذف `AI_MODE` (يعود إلى `draft`).
**لإيقاف المساعد كلّه:**

```sql
alter table public.support_messages disable trigger support_messages_dispatch_agent;
```

ولإعادته: `enable trigger` بدل `disable`.

## ٤. تحديث قاعدة المعرفة

أضفت ميزة؟ غيّرت سعر باقة؟ **المساعد لا يعرف إلا ما في الملفّ.**

١. عدّل `docs/support-knowledge-base.md`.
٢. شغّل:

```bash
export SUPABASE_FUNCTIONS_URL=https://<ref>.supabase.co/functions/v1
export SUPABASE_ANON_KEY=<anon>
export SUPPORT_INGEST_SECRET=<secret>

./scripts/kb-ingest.sh --dry-run   # الخطّة: بلا كتابة وبلا كلفة
./scripts/kb-ingest.sh             # الفهرسة
```

★ **ما لم يتغيّر لا يُعاد حساب متجهه** (بصمة SHA-256 لكل مقطع)، فإعادة
الفهرسة بلا تعديل تكلّف **صفرًا**. وتعديلُ سطرٍ واحد كلّف ٢٤ متجهًا من
٣٥ حين غيّرنا المعايرة.

**وقياس جودة الاسترجاع** قبل أن يراه تاجر:

```bash
./scripts/kb-ingest.sh --probe "ليه منتجي ظاهر نفد؟" "كيف اضيف الوان؟"
```

يعرض أقرب المقاطع ودرجة تشابه كلٍّ منها.

## ٥. الأمن — أين الجدران

| الطبقة | الجدار |
|---|---|
| نداء المساعد | سرّ `x-support-secret` (مقارنة بزمن ثابت على بصمة SHA-256) |
| بوت تلغرام | سرّ الترويسة **+** أن تكون المحادثة **والضاغط** صاحبَ المنصّة **+** فعلٌ من اثنين بمعرّف UUID |
| نفاذ القاعدة | قائمة معلَنة: أربعة جداول `support_*` ودالّتان — وحارسٌ في الاختبارات يمنع تسلّل غيرها |
| كتابة الردّ | `ai_support_reply` — باب ضيّق، ممنوحٌ لـ`service_role` وحده، و`anon` و`authenticated` ممنوعان |
| أعمدة التذكرة | مُسمّاة واحدًا واحدًا — `related_payment_id` لا يدخل سياق النموذج أصلًا |
| سرّ المحفّز | في **Vault** لا في نصّ الهجرة (نصّ الدالّة يظهر في كل نسخة احتياطية) |

★★★ **ونصّ التاجر بيانات لا أوامر.** يُحاط بفاصل، وسطرٌ يحاول تقليد
الفاصل يُكسَر. والحدّ الحقيقي ليس جملةً في التعليمات بل **قلّة ما
يملكه النموذج**: لا أدوات، ولا قاعدة بيانات، ولا في سياقه إلا مقاطع
ملفٍّ عامّ ونصّ التذكرة. فأسوأ ما يبلغه حقنٌ ناجح: جوابٌ خاطئ لنفس
التاجر — لا تسريب ولا تنفيذ.

### الإفصاح

في وضع `auto` يُلحق بالردّ سطرٌ يقول إنه آليّ ويدلّ على طريق الإنسان.
★★★ ولماذا: الرسالة تُكتب `author_kind = 'staff'` فيراها التاجر «فريق
الدعم». في وضع المسوّدة قرأتَها وأرسلتَها فالكلام كلامك؛ وفي `auto` لم
يقرأها أحد ⇒ عرضها كبشريّة **تضليل**.

### تدوير الأسرار

★ **تبديل سرٍّ ليس نافذًا لحظة تبديله.** متغيّرات البيئة تُحقَن في
الدالّة **وقت إقلاعها**، فالنسخة الساخنة تحمل القيمة القديمة حتى
تخمد أو يُعاد نشرها. (مُجرَّب: سرٌّ بُدِّل بقي يعمل خمس عشرة دقيقة.)
فإن سُرّب سرٌّ: بدّله **وأعد نشر الدالّة** فورًا.

- **رمز بوت تلغرام:** `/revoke` في @BotFather ⇒ رمزٌ جديد ⇒ بدّل
  `TELEGRAM_BOT_TOKEN` ⇒ أعد `setWebhook` بالرمز الجديد.
- **سرّ المحفّز:** `select vault.update_secret(id, '<new>')` **و**
  `SUPPORT_WEBHOOK_SECRET` في أسرار الدوالّ — القيمتان يجب أن تتطابقا.

## ٦. حين لا يعمل شيء — ابحث هنا بالترتيب

**١) هل نُودي المساعد أصلًا؟**

```sql
select id, status_code, left(content, 300) as body, error_msg, created
  from net._http_response order by created desc limit 5;
```

- لا صفوف ⇒ المحفّز لم يعمل. افحص: `author_kind = 'requester'`؟
  المحفّز مفعَّل؟ السرّان في Vault؟
- `status_code = 401` ⇒ السرّان لا يتطابقان (Vault ≠ أسرار الدوالّ).

**٢) ماذا قرّر المساعد؟**

```sql
select action, status, confidence, reason, error, model,
       input_tokens, output_tokens, created_at
  from public.support_ai_logs order by created_at desc limit 10;
```

| `status` | معناه |
|---|---|
| `sent` | أُرسل للتاجر |
| `pending` | مسوّدة تنتظرك في تلغرام |
| `escalated` | حُوّلت إليك — `reason` يقول لماذا |
| `declined` | ضغطت «لا ترسل» |
| `failed` | عطل — `error` يحمل نصّه |

**٣) سجلّ الدالّة** (Supabase ← Edge Functions ← Logs). كل فشلٍ يحمل
**رمز ارتباط** يُعاد للمستدعي ويُسجَّل خادميًّا:
`support_agent_failed` · `telegram_notify_failed` ·
`telegram_webhook_failed` · `kb_ingest_failed`.

★ `STATUS_NOT_CHANGED` في عمود `error` ⇒ الردّ **وصل** لكن حالة
التذكرة لم تتغيّر. الطابور يكذب — ابحث عن السبب، لا تتجاهله.

## ٨. ما لم يُبنَ بعد

- **لا يقرأ المرفقات.** تاجرٌ يرسل صورة شاشة: المساعد يقرأ نصّه وحده.
- **لا يرى بيانات التاجر.** لا يعرف كم منتجًا عنده ولا حالة اشتراكه —
  وهذا **قيدٌ مقصود** (القاعدة ٥)، لا نقص.
- **دورٌ واحد لكل تذكرة.** لا يتابع محادثةً بعد ردّه الأوّل.
- **التجّار وحدهم.** الزبائن والشركاء يُحوَّلون إليك.
