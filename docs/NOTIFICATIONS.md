# 14. Notification Architecture

## 14.1 القنوات في v1

| القناة | الحالة |
|---|---|
| **In-app** (`notifications` + Notification Center) | ✅ أساسية |
| **Email** (`email_outbox` + مزوّد مجرّد) | ✅ أساسية |

## 14.2 البنية

```
حدث في النظام (تغيّر حالة طلب، دفعة، تذكرة…)
      │
      ▼
notify(event, recipients[], payload)
      │
      ├──▶ notifications (in-app)  · dedupe_key
      └──▶ email_outbox (queued)   · dedupe_key
                 │
            pg_cron كل دقيقة → Edge Function
                 │
            EmailProvider.send()  ← واجهة مجرّدة
                 ├─ sent   → sent_at
                 └─ failed → attempts++ · تراجع أسّي · بعد 5 محاولات: failed + تنبيه
```

```ts
// lib/email/provider.ts — تبديل المزوّد لا يمسّ أي كود آخر
export interface EmailProvider {
  send(msg: { to: string; template: TemplateId; data: Record<string, unknown>;
              locale: 'ar' }): Promise<{ id: string }>;
}
```
> المزوّد الفعلي في v1 — سؤال **Q10**. القوالب بالعربية RTL مع نسخة نصية.

## 14.4 منع التكرار (Deduplication)

```
dedupe_key = "<event>:<resource_id>:<recipient_id>[:<bucket>]"
مثال: "subscription.expiring:sub_123:user_456:d7"
```
مع `unique (user_id, dedupe_key)` ⇒ `INSERT ... ON CONFLICT DO NOTHING`.

**لماذا هذا حاسم؟** لأن مهام pg_cron قد تُعاد أو تتأخر أو تتداخل؛ بدون
هذا المفتاح يستيقظ التاجر على 12 رسالة «اشتراكك على وشك الانتهاء».
نفس المفتاح على `email_outbox` ⇒ لا بريد مكرر ولو أُعيدت المحاولة.

## 14.5 Notification Center

`/dashboard` و`/admin` و`/partner`: جرس + عدّاد غير المقروء.

- قراءة/غير مقروء (`read_at`) · «تعليم الكل كمقروء».
- كل إشعار له `link` ينقل إلى المورد **بعد فحص الصلاحية** — إشعار لا يمنح
  وصولًا؛ فقد المستخدم الصلاحية ⇒ الرابط يعيد `NOT_FOUND`.
- Pagination (20/صفحة) — لا تحميل كامل السجل.
- تصفية بالنوع وبغير المقروء.
- تفضيلات لكل تاجر (`store_settings.notification_prefs`): أي أنواع
  تصله بالبريد. **التنبيهات الأمنية والمالية غير قابلة للإيقاف.**
- **التحديث:** Polling كل 60 ثانية وقت نشاط الصفحة فقط. Supabase Realtime
  خيار لاحق — تجنّبناه في v1 لأنه يستهلك اتصالات Free Tier بلا داعٍ.
- تنظيف: حذف المقروءة الأقدم من 90 يومًا (Job ليلي).

## 14.6 موثوقية البريد

| الخطر | المعالجة |
|---|---|
| فشل المزوّد | صف في `email_outbox` يبقى ويُعاد بتراجع أسّي (1د·5د·30د·2س·12س) |
| بريد مكرر | `dedupe_key unique` |
| إرسال داخل الطلب | ❌ ممنوع — دائمًا عبر الطابور |
| حد مزوّد البريد | تحكم في معدل التصريف داخل الـJob |
| بريد Supabase Auth المدمج | ⚠️ محدود جدًا وغير إنتاجي ⇒ **SMTP مخصص إلزامي** حتى لرسائل التأكيد |
| تسريب بيانات في البريد | لا مبالغ ولا بيانات بنكية ولا روابط ملفات خاصة — رابط دخول فقط |
