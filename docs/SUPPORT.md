# 15. Support System — نظام تذاكر الدعم

> تذاكر مهيكلة، **وليس شات عامًا**. لا يوجد أي نظام مراسلة داخلي آخر
> في المنصة (محسوم في المواصفات §27).

## 15.1 المكوّنات
`support_tickets` · `support_messages` · `support_internal_notes` (جدول
**منفصل**) · `support_attachments` · `support_events`.

## 15.2 من يفتح تذكرة؟
التاجر من لوحته · العميل من حسابه/متجره · الشريك من لوحته · زائر عبر
`/contact` (بعد تحقق مضاد للسبام). قنوات خارجية (واتساب) تُعرض كوسيلة
إضافية، لا كبديل.

## 15.3 حالات التذكرة

```
new ──▶ open ──▶ in_progress ──▶ resolved ──▶ closed
 │        │           │  ▲            │           ▲
 │        │           ▼  │            │           │
 │        │   waiting_customer ───────┘           │
 │        │   waiting_internal                    │
 │        └─────────────────────────────────────▶ │
 └──────── closed (إغلاق مباشر من موظف) ──────────┘
```

| الانتقال | من يملكه |
|---|---|
| `new → open` | موظف دعم (فتح/استلام) |
| `open → in_progress` | الموظف المعيَّن |
| `→ waiting_customer` | موظف دعم (بعد رد) |
| `→ waiting_internal` | موظف دعم |
| `waiting_customer → in_progress` | **تلقائيًا** عند رد صاحب التذكرة |
| `→ resolved` | موظف دعم |
| `resolved → closed` | تلقائيًا بعد 7 أيام بلا رد، أو يدويًا |
| `closed → open` | إعادة فتح — خلال 14 يومًا، بعدها تذكرة جديدة مرتبطة |

**الإنفاذ:** دالة `transition_ticket()` ترفض أي انتقال غير مذكور أعلاه
وأي انتقال بلا صلاحية، وتكتب في `support_events`.

## 15.4 البيانات
رقم تذكرة فريد (`NM-2026-000123`) · صاحب الطلب ونوعه · المتجر المرتبط ·
الموضوع · التصنيف (`technical, billing, subscription, orders, domains,
account, other`) · الأولوية (`low, normal, high, urgent`) · الحالة ·
الموظف المسؤول · طوابع SLA (`created_at`, `first_response_at`,
`resolved_at`, `closed_at`, `last_message_at`) · روابط اختيارية إلى
طلب/دفعة/اشتراك.

## 15.5 الرسائل والملاحظات الداخلية

- كل رسالة صف دائم في القاعدة (لا حالة واجهة).
- ترتيب زمني + وقت وتاريخ + حالة الإرسال.
- **الملاحظات الداخلية في جدول منفصل** لا عمود `is_internal`:
  خطأ استعلام واحد لا يمكن أن يسرّبها، ولا توجد أي سياسة RLS تمنح صاحب
  التذكرة قراءتها.
- المرفقات في `support-attachments` (خاص) عبر Signed URL قصير العمر.
- تنقية كل نص عند التخزين والعرض (XSS).

## 15.6 لوحة فريق الدعم

قائمة بالبحث والفلترة (حالة · أولوية · تصنيف · تاجر · موظف · تاريخ)
وترتيب · فتح التذكرة بكامل المحادثة · تعيين موظف · تغيير الحالة/الأولوية/
التصنيف · الرد · ملاحظة داخلية · تصعيد · ربط بطلب/دفعة/اشتراك ·
سجل نشاط (من فعل ماذا ومتى) · إحصائيات (جديدة · مفتوحة · محلولة · مغلقة ·
متوسط زمن الاستجابة والحل).

## 15.7 العزل والصلاحيات

| الفاعل | يرى |
|---|---|
| التاجر | تذاكره هو + تذاكر متجره — **لا شيء من متجر آخر** |
| العميل | تذاكره هو فقط |
| الشريك | تذاكره هو فقط |
| موظف دعم | حسب `support` في `admin_permissions` |
| Admin Owner | الكل |

**قواعد غير قابلة للخرق:**
- مستخدم من متجر A لا يصل إلى تذاكر متجر B (اختبار عزل إلزامي).
- موظف الدعم **لا يرى البيانات المالية** لمجرد فتحه تذكرة فاتورة — يرى
  وجود الدفعة وحالتها فقط، لا المبلغ ولا الإثبات (راجع Data Access Matrix).
- كل إجراء حسّاس في `audit_logs`.

## 15.8 الإشعارات
تذكرة جديدة → فريق الدعم · رد من الدعم → صاحب التذكرة (in-app + بريد) ·
رد من المستخدم → الموظف المعيَّن · تغيير حالة ذي معنى → صاحب التذكرة.
كلها بـ`dedupe_key` يمنع التكرار عند إعادة المحاولة.

## 15.9 الاحتفاظ والبحث
- التذاكر **لا تُحذف** بإغلاق حساب، خصوصًا المرتبطة بعملية مالية أو نزاع
  أو إجراء إداري (§8 من الإضافات).
- الاحتفاظ بالتذاكر المغلقة: **24 شهرًا** (D26).
- بحث نصي في المواضيع والرسائل **ضمن نطاق صلاحية الفاعل فقط**.
- Pagination إلزامي (20 تذكرة / 50 رسالة) — لا تحميل السجل كاملًا.

## 15.10 الأمان والاختبارات
عزل التذاكر بين المتاجر · الأدوار والصلاحيات · رفع المرفقات (نوع/حجم/
وصول) · Rate Limiting وSpam · منع تكرار الرسائل · الإشعارات · انتقالات
الحالة · سجل التدقيق · الأداء مع عدد كبير من التذاكر (Pagination).
